### **Section 13.3: What's Missing: Error Handling, Security, Performance (Pages 9-14)**

**【Manga Part】**

**Manga Scene 4 (Page 9):**
- **Panel 1:** David explains: "Let's understand **what's missing** in AI-generated code."
- **David:** "AI-generated code often lacks **error handling, security, performance**. For example, when trying to read a non-existent file in `log.py`, **without error handling**, the program stops. Adding error handling lets you **handle errors safely**."

**Panel 2:** Alex asks: "What specifically are error handling, security, and performance?"
- **David:** "(1) **Error handling**: When trying to read a non-existent file, handle errors safely (e.g., use `try-except` blocks), (2) **Security**: When receiving user input, prevent malicious input (e.g., validate input), (3) **Performance**: When processing large amounts of data, process efficiently (e.g., optimize loops)."

**Panel 3:** Alex leans forward: "I want to actually check what's missing in `daily_log`."
- **David:** "Let's look at `log.py` and check if **error handling, security, performance** are in place. Ask Cursor's **Chat** 'Review `log.py` code and check if error handling, security, and performance are in place' and it will tell you what's missing."

**【Infographic Part】**

**Pages 9-10:**
- **What's missing in AI-generated code:**
  1. **Error handling**: When trying to read a non-existent file, handle errors safely
  2. **Security**: When receiving user input, prevent malicious input
  3. **Performance**: When processing large amounts of data, process efficiently

- **Error handling examples:**
  | Situation | Problem | Solution |
  |-----------|---------|----------|
  | **Reading non-existent file** | Stops with error | **Use `try-except` blocks** |
  | **Processing invalid input** | Stops with error | **Validate input** |
  | **Network errors occur** | Stops with error | **Add error handling** |

**Pages 11-12:**
- **Security examples:**
  | Situation | Problem | Solution |
  |-----------|---------|----------|
  | **Receiving user input** | May receive malicious input | **Validate input** |
  | **Receiving file paths** | May receive invalid paths | **Validate paths** |
  | **Calling external APIs** | May send invalid requests | **Validate requests** |

**Pages 13-14:**
- **Performance examples:**
  | Situation | Problem | Solution |
  |-----------|---------|----------|
  | **Processing large amounts of data** | Processing is slow | **Optimize loops** |
  | **Reading files** | Reading is slow | **Use buffering** |
  | **Accessing database** | Access is slow | **Use indexes** |
